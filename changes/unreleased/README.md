# Фрагменты CHANGELOG

Каждый PR, меняющий поведение, кладёт сюда **свой файл** `<ветка>.md` — например
`changes/unreleased/human-labels.md`, — а раздел «Не выпущено» в `CHANGELOG.md` не
трогает. Параллельные PR тогда не конфликтуют на одном месте файла.

Формат — пункты списка, как в `CHANGELOG.md`:

```markdown
- **Коротко, что изменилось.** Почему и что увидит пользователь; миграции, гранты,
  шаги при обновлении.
```

При релизе (только с чистого дерева: фрагменты закоммичены, в `changes/`,
`CHANGELOG.md` и `VERSION` нет незакоммиченных и staged-изменений)
`scripts/changelog-release.sh <версия>` собирает фрагменты (и записи,
оставшиеся в «Не выпущено») в раздел `## <версия> — <дата>` и удаляет файлы. CI
отклоняет PR, который правит `CHANGELOG.md` без смены `VERSION`.
