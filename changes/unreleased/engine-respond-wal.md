- **Автоответ: потолок блокировок подсети и запись вперёд для всех инцидентов.**
  - **Потолок.** `respond.block_cap` и `respond.block_cap_window` в правиле, по
    умолчанию 32 новых адреса на подсеть (/24, /48) за час. Это дополнительно к
    `max_targets`.
  - **Одна попытка — один путь.** Каждый адрес инцидента идёт через автомат с
    единственным владельцем: снимок режима → место в потолке → запись-резерв в
    `response_log` → исполнитель → итог. Без записанного резерва исполнитель не
    вызывается. Повторы после отказа исполнителей проходят тем же путём.
  - **Восстановление.** После рестарта решения и места восстанавливаются по последней
    записи журнала. Пока журнал не прочитан, новых блокировок нет.
  - **Адреса.** Они приводятся к канонической записи: IPv4 из `::ffff:…`, без зоны.
  - **Обновление.** Миграция 0037 добавляет `response_log.step`. Сразу после выкатки у
    старых записей шага нет, по ним ничего не восстанавливается: открытые инциденты
    по-прежнему считаются решёнными, как и раньше.
