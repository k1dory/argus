- **«Субъекты»: пределы HTTP ClickHouse проверяются по тому, что реально уходит.**
  - **Поле URL — в percent-encoded виде.** ClickHouse 24.8 (HTMLForm) меряет поле URL до
    декодирования: 60 КБ кириллицы или иероглифов в URL — это 180 КБ, больше предела
    128 КиБ. Части массивов-параметров делятся по длине в URL (как сериализует
    `URLSearchParams`), поэтому подходят и для URL, и для multipart.
  - **URI — как его собирает `URLSearchParams`.** Выбор между URL и multipart идёт по
    собранному URL, а не по оценке через `encodeURIComponent` (`~` там уже `%7E`): запрос
    больше не получает 414 на границе 1 MiB.
  - **Явная ошибка вместо отказа сервера.** Если запрос не помещается ни в URL, ни в
    multipart, консоль не отправляет его и сообщает размеры.
  - **Персона с тысячами алиасов** (снимки адресов VPN каждые 5 минут). При больше чем
    64 алиасах предикат персоны строится как в подсчёте активности: `transform` по
    значению даёт отрезок номеров интервалов, интервалы — массивами-параметрами. Текст
    SQL не растёт с числом алиасов: подсчёт инцидентов больше не упирается в
    `max_query_size` (256 КиБ) и в предел поля формы, а память не зависит от числа
    значений. Отбор строк тот же, что у веток `OR` (проверено на живом ClickHouse). Партия
    инцидентов не больше 64 КиБ SQL; если одна персона её превысит, список падает с
    явной ошибкой.
