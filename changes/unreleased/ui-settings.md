- **Правила корреляции: таблица видна и без движка, шумные — сверху.** Когда движок
  не отвечает, страница показывает правила с инцидентами за 30 дней из хранилища и
  их долю ложных под общей плашкой «Движок корреляции недоступен». Название правила
  стоит первой колонкой (ID — под ним), правила отсортированы по доле ложных, а шумные
  (не меньше половины ложных при 5+ инцидентах) выделены. Число инцидентов ведёт к их списку.
- **Согласие с агентом: порядок по нижней границе 95 % интервала.** Правило с 1 ложным
  из 2 больше не обгоняет правило с 3 из 7; правила, у которых меньше 20 ответов,
  собраны в свёрнутую группу. В ячейке одна строка «43 % 3 из 7», колонки и плитки
  названы по-человечески, методика — в раскрытии «Как считается», есть ссылка назад
  к правилам.
- **Настройки разбиты на вкладки.** Учётная запись, пользователи, реагирование,
  исключения, журнал действий, система. Режим реагирования нельзя применить, пока
  движок не отвечает (кнопка неактивна, причина написана рядом); включение IPS
  требует подтверждения. Журнал реагирования — лентой по дням («Заблокирован
  203.0.113.7 на ngfw.edge», отказы выделены), журнал действий — таблицей с
  заголовками и подписями по-русски. У администратора без 2FA на всех вкладках
  видно предупреждение. Сбой хранилища показывается внутри своей панели, а не
  вместо половины страницы.
- **Вход: логин не стирается после неверного пароля.** React 19 сбрасывал форму
  после действия; теперь логин возвращается из ответа сервера, фокус переходит на
  пароль. Подсказка про стартовый пароль admin видна, только пока он не сменён;
  корпоративный вход (SSO) — первой кнопкой; «группа не даёт доступа к ARGUS»
  (`/login?sso=no_role`) отличается от отказа IdP.
