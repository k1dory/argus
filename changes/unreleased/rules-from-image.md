- **Несовместимо: в проде поставляемые правила движок берёт из образа, а не из `./rules` на хосте.**
  - `RULES_DIR=/usr/share/argus/shipped/rules` (та же копия, что у реестра) — версия правил всегда равна версии движка. Обновление кода на хосте больше не меняет правила под работающим старым движком: на rc34 так появился дубль INC-5312.
  - Свои правила — отдельный каталог `RULES_USER_DIR` (compose: `/etc/argus/rules.d`, на хосте — `ARGUS_USER_RULES_DIR`, по умолчанию `./rules.d`; роль `argus` — `/etc/argus/rules.d`, `argus_user_rules_src`). Пользовательское правило с `id` поставляемого отвергается, а не подменяет штатный детект; сбой разбора каталога отвергает его целиком, движок работает на поставляемых. Отказ — тем же путём, что и у поставляемых (#99): журнал, метрика `argus_engine_rules_rejected`, событие `argus.system` / `rules.rejected` (`attrs.reason: shipped_id_taken` | `duplicate_id` | …), `rules.recovered` и сохранение прежней версии отвергнутого файла при перечитывании.
  - **`object` событий `rules.rejected` / `rules.recovered` — файл с префиксом каталога**: `shipped/ops/x.yml` или `user/x.yml` (`user/` — пользовательский каталог отвергнут целиком). #99 и #111 выходят вместе (rc36), прежнего формата в проде не было.
  - **Кто правил `./rules` на хосте**, должен перенести свои правки в `RULES_USER_DIR` под своими `id` — после обновления правки в `./rules` движок не видит.
  - Стенд (`make up-dev`, e2e) и `./scripts/argus rules test` по-прежнему читают `./rules`.
  - Файлы правил читаются только обычные (FIFO, устройство — отказ, без зависания старта и перечитывания), не больше 1 МиБ; отпечаток каталога учитывает права; происхождение правила (поставляемое или своё) — по каталогу загрузки, а не по префиксу пути.
  - `engine rules test` без `--dir` проверяет тот же набор, что движок и `rules list` (поставляемые и `RULES_USER_DIR`); с `--dir` — только этот каталог. `./scripts/argus rules list` через Docker показывает набор работающего движка, `rules test` — по checkout.
  - Фикстуры в образе — `/usr/share/argus/shipped/fixtures/events/`, как в репозитории: встроенные тесты правил образа находят их; реестр читает тот же путь.
