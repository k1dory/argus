- **«Субъекты»: большой справочник персон и общие значения алиасов.**
  - **Большие параметры.** Параметры длиннее 64 КБ теперь уходят телом
    `multipart/form-data`, а не в URL. URI ClickHouse не длиннее 1 MiB, и тысяча персон
    с длинными uid давала HTTP 414. Длинные массивы делятся на части не больше 60 КБ в
    байтах UTF-8 и склеиваются в запросе (`arrayConcat`): у поля формы предел 128 КиБ.
    Вложенных массивов-параметров нет: классы одного значения и владельцы класса — отрезки
    плоских массивов, поэтому тысяча интервалов одного IP тоже делится.
  - **Длинный SQL.** В multipart запрос — тоже поле формы с тем же пределом. SQL длиннее
    120 КБ уходит телом `text/plain`, параметры — в URL, пока он помещается. Подсчёт
    инцидентов делится на партии не больше 64 КБ SQL.
  - **Общие значения.** Подсчёт активности группирует строки по набору совпавших классов
    алиасов и сводит наборы до персон в том же запросе. Сотни персон с общим значением не
    размножают строки событий, а в ответе не больше строк, чем персон: предел
    `max_result_rows` больше не обрезает счётчики молча. Если ответ всё же дошёл до
    предела, список падает с ошибкой, а не показывает неполные числа.
