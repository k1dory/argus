- **Миграция ключа склейки (`group_by_previous`) — только инцидентов, заведённых до смены.**
  - Движок записывает в инцидент `group_by`, по которому он заведён (миграция 0039, колонка
    `incidents.group_by`); подхват — только если он равен `group_by_previous`. Инцидент,
    заведённый или уже перенесённый по текущему `group_by`, не подхватывается, и после
    рестарта тоже.
  - Строки до 0039 (`group_by` пуст) подхватываются только с явной границей
    `group_by_previous_before` (созданы раньше неё). У `a41c-ops-067` — время слияния #88:
    INC-5312 на argus1 (создан 2026-11-01 17:46:16) продолжится, инциденты rc34 — нет.
  - Прежний ключ считается той же функцией, что у движка (`eval.GroupKey`, с резервом на
    субъект), а не копией.
  - Поддержан переход к группировке по субъекту, узлу или адресу: новый `group_key` пуст.
- **Правила: явная схема полей вместо молчаливого пропуска.**
  - Метаданные (`description`, `author`, `references` и т. п.) разрешены; неизвестное поле
    верхнего уровня — предупреждение с файлом и строкой, правило работает.
  - Неизвестное поле внутри `detection`, `threshold`, `respond`, `analyst` — отказ только этого
    правила: остальные загружаются, при перечитывании для него остаётся прежняя версия, при
    старте оно пропускается с ошибкой в журнале (движок стартует).
  - `POST /reload` при отказе — 422 с файлами и причинами; метрики
    `argus_engine_rules_reload_failures_total`, `argus_engine_rules_rejected`.
  - Живой случай argus1: rc33 перечитал смонтированное правило с новым `group_by` и
    проигнорировал `group_by_previous`, завёл INC-5370 рядом с открытым INC-5312.
- **Реестр: совпавший ключ записывает текущий `group_by`.** Если ключ при новом `group_by` не
  изменился, инцидент помечается текущей группировкой и записывается без новых событий —
  соседняя группа его больше не забирает.
- **Реестр: подхват без `group_key` — только строк до 0039 у правил без `group_by_previous`.**
  С записанным `group_by` пустой ключ — это группировка по субъекту или значение «-»; у правила
  с `group_by_previous` решает миграция с её проверками (`group_by`, граница).
- **Правила: схема по развёрнутому дереву.** YAML-алиасы и `<<` применяются до проверки:
  `detection: *options` с неизвестным полем отвергается, корректный вложенный `<<` работает.
- **Правила: `id` уникален.** Повтор `id` — отказ (`duplicate_id`): при перечитывании
  остаётся правило того файла, что был активен с этим `id` (в том числе сохранённая версия
  отвергнутого файла), при старте — файл, первый по пути; остальные отвергаются.
  Нестроковый ключ в структурах детекта — тоже отказ правила.
- **Отказ правила виден.** Событие `argus.system` / `rules.rejected` (`object` — файл,
  `attrs.rule_id`, `attrs.reason` — код без содержимого правила, `attrs.transport: internal`)
  и `rules.recovered`, когда файл загружен, а инцидент отказа по нему открыт (по реестру —
  переживает рестарт и временное удаление файла); правило `a41c-ops-068` (`rules/ops/rules-rejected.yml`)
  с тестом на фикстуре; метрика `argus_engine_rules_rejected`.
