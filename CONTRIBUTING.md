# Участие в разработке ARGUS

Спасибо за вклад. Перед работой прочитайте [README](README.md) и
[политику безопасности](SECURITY.md). Не добавляйте в задачи, PR и тестовые
фикстуры настоящие события, персональные данные, токены и пароли.

## Изменения

1. Сначала опишите проблему и ожидаемое поведение в задаче. Для исправления
   ошибки приложите обезличенный пример события или шаги воспроизведения.
2. Делайте небольшие PR с объяснением влияния на приём событий, расследование
   и обновление существующей установки. Изменения схемы ClickHouse добавляйте
   новым идемпотентным файлом в `clickhouse/migrations/`; уже применённые
   миграции не редактируйте.
3. Для правил добавляйте тестовые события и ожидаемые срабатывания в
   `fixtures/` и `rules/tests/`. Для изменений поведения кода добавляйте тест,
   который воспроизводит ошибку или проверяет значимый сценарий.
4. Обновляйте README при изменении настроек. Изменение поведения для пользователя —
   файл `changes/unreleased/<ветка>.md` (формат — в `changes/unreleased/README.md`);
   `CHANGELOG.md` правит только релиз (`scripts/changelog-release.sh`), CI это проверяет.
   Не включайте в PR `.env` и локальные данные.
5. В `main` не пушат напрямую — ни люди, ни агенты: работайте в отдельной
   ветке и открывайте PR в `main`. Пока репозиторий приватный на бесплатном
   плане GitHub, ruleset `protect-main` не применяется, и для людей это
   договорённость. Агентов Claude Code от случайного push в `main` страхует
   хук из `.claude/settings.json`.

## Ревью

На каждый PR в `main` автоматически приходит ревью Claude Code
(`.github/workflows/claude-review.yml`): inline-комментарии с приоритетом
P1 (потеря данных, безопасность, падение) или P2 и итоговый комментарий.
Замечания P1 исправляются до слияния; на P2 ответьте исправлением или
объяснением в треде. Новый пуш в ветку PR запускает ревью заново.
Черновики и PR из форков автоматически не ревьюятся.

## Локальная проверка

```sh
make test
make check
make lint
```

Для консоли: `cd web && npm test && npm run lint && npm run typecheck`; тест живого
ClickHouse (`tests/triage-claim-ch.test.ts`) выполняется при заданном
`ARGUS_TEST_CLICKHOUSE_URL`, иначе пропускается. Для конкретного Go-модуля:
`cd collector && go test ./...` (аналогично `engine`, `policyd`, `mcp`, `triage`).
Правила — `./scripts/argus rules test`. На живом стенде (`make up-dev && make demo`) —
`./scripts/api-smoke.sh`: контракты API консоли для агентов. CI дополнительно
собирает образы и на push в `main` гоняет `./scripts/e2e.sh` (стек с нуля, replay,
инциденты, тот же смоук). Слои тестов описаны в README, раздел «Тесты»; изменение
маршрута `/api/*` сопровождайте правкой `api/openapi.yaml`.

## Совместимость

Новый релиз должен читать данные и конфигурацию предыдущего релиза без
ручной правки базы. Если требуется пересборка таблицы или остановка записи,
приложите отдельный план обновления, отката и проверки сохранности данных.
